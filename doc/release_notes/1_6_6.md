### 1.6.6

#### Improvements

* `:oauth_dynamic_client_registration` feature: client metadata which the server does not understand is now ignored, as mandated by [RFC 7591](https://datatracker.ietf.org/doc/html/rfc7591#section-3.1), instead of failing the registration with an `"invalid_client_metadata"` error.

  **Behaviour change**: a registration request carrying metadata the server has no column or auth value method for used to be rejected, and now succeeds, with the unknown metadata left out of both the registration and the registration response. Metadata the server does understand but the client may not set, such as `"client_id"` or `"account_id"`, still fails the request, as does metadata with an unsupported value, and so do missing required params.

  If your authorization server wants to keep failing those requests, you can do your own check on the registration body in the `before_register` hook.
